# Fat2Fit / Scope 0.3

**Пользователи:** один тренер, его ученики. Архитектура рассчитана на независимые тренерские workspace, но самообслуживание тренеров пока не включено.

## Приоритет №1: полный вертикальный сценарий

Тренер создаёт упражнение -> создаёт шаблон -> назначает ученику -> ученик в мобильном Telegram отмечает подходы -> данные сохраняются на сервере -> тренер видит результат. Каждый приём данных проверяет роль и workspace.

## Модель данных

- `users` — идентичность Telegram, язык;
- `workspaces` и `memberships` — изоляция и роли;
- `invitations` — одноразовый токен (в БД хранится SHA-256);
- `exercises` — общая и личная библиотека, локализованные метаданные, URL фото/видео;
- `workout_templates` + `template_exercises` — редактируемые шаблоны;
- `assignments` + `assignment_exercises` — снимок плана для конкретного ученика;
- `set_logs` — фактические подходы.

## Принятые продуктовые ограничения

Только зал: подходы, повторения, вес, отдых. Для планки на MVP использовать поле «повторения» как секунды (потребует отдельных units в 0.4). Отсутствуют групповые занятия, платежи, программы по неделям, внешние сервисы и AI. В Mini App язык выбирается учеником/тренером независимо. Для русского, английского и сербского интерфейса заложен fallback переводов карточки упражнения.

## Acceptance criteria для пилота

1. Настоящая Telegram-авторизация без логинов;
2. Запрет доступа без приглашения, кроме bootstrap-тренера;
3. Тренер может создавать свои упражнения и шаблоны;
4. Ученик видит только свои назначения;
5. Выполненные подходы сохраняются при повторном входе;
6. Отчёт тренера отражает реальные данные;
7. Обновление шаблона не меняет назначения за прошлые даты;
8. Проверены все три языка и мобильные ширины.

Пока эти критерии не проверены в рабочем окружении, статус — **engineering preview, не pilot-ready**.
